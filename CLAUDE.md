# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

**IBRÆ** ("A different layer of your desktop"; formerly "Dynamic Island"): a macOS-style dynamic island for Windows and Linux (Fedora/Debian), built with **Tauri 2 + Rust + Svelte 5**. Panels: Claude Code activity, music, focus timer, quick notes, system stats, calendar, settings. All user-facing text (UI, CLI errors, tray menu, README, installer) is in **Spanish**; code comments and commit messages are in English (`feat: …`, `release: vX.Y.Z`).

## Commands

Requires Node 20+ and Rust (MSVC toolchain on Windows; WebKitGTK dev libs on Linux — see README).

```sh
npm install
npm run tauri dev        # dev with hot reload (builds island-hook first, then vite on :1420)
npx tauri build          # installers → src-tauri/target/release/bundle/{nsis,msi,deb,rpm}
npm run build:hook       # build island-hook and copy it to src-tauri/binaries/island-hook-<triple>
npm run build            # frontend only → dist/
cd src-tauri && cargo check / cargo clippy   # Rust only (workspace includes the `hook` crate)
npm run release -- 0.1.4 # bump version in package.json, package-lock, tauri.conf.json, Cargo.toml/lock; commit, tag, push
```

Tests: `npm test` (Vitest: UI logic in `src/lib/*.test.js`, e.g. what the pill shows and how wide it is, from `src/lib/pill.js`) and `cd src-tauri && cargo test --workspace` (one module, e.g. `cargo test -p ibrae claude::tests`). `.github/workflows/test.yml` runs both on every push to main and every PR (Rust on Windows and Linux). Keep UI decisions that can be tested as pure functions in `src/lib/` (like `pill.js`) rather than inline in components. There is no linter. UI verification is otherwise manual or via the Linux Docker scripts in `ci/` (each Dockerfile's header has the exact `docker build`/`docker run` lines): `linux.Dockerfile` is the base build image, `linux-bundle.*` produces `.deb`/`.rpm` into `dist-linux/` (needs `dist/` built on the host first), `linux-smoke.*` runs the app on Xvfb, feeds it Claude hook events through `island-hook`, screenshots it, and checks that a second instance exits.

`ISLAND_PEEK=home,claude,music,focus,notes,sys` opens each panel in turn at startup (for screenshots). `ISLAND_DEMO=1` starts with no real data and ignores the cursor (no Claude channel, player, calendars, update checks, hook repair or hover tracking) so a demo can be driven by emitting events; `scripts/record-demo.mjs` uses it to record `docs/demo.gif`.

Pushing a `v*` tag triggers `.github/workflows/release.yml`, which builds on Windows + Linux and uploads NSIS, MSI, portable .zip (with `.github/portable-LEEME.txt`), .deb, .rpm, .AppImage and `latest.json` to the GitHub release.

## Architecture

**Core pushes, UI listens.** Rust owns all state (`*State` structs registered with `.manage()` in `main.rs`) and emits Tauri events (`settings`, `claude`, `claude-perm`, `audio`, `media`, `media-art`, `focus`, `calendar`, `update`, `hover`, `covered`, `peek`, `open-tab`). `src/lib/store.svelte.js` holds Svelte 5 `$state` mirrors, loads snapshots via `invoke` once in `init()`, then only updates from events — the UI never polls the core. The clock ticks once a minute unless something on screen shows seconds (`setClockSeconds`). This design is deliberate for low CPU/RAM; keep new features event-driven and avoid emitting when nothing changed (see `Track::same_as` in `media/mod.rs`).

Adding a command means: `#[tauri::command]` fn in its module → register in `generate_handler!` in `main.rs` → call via `invoke` from the store/component. `settings.rs` is the source of truth for settings; the defaults object in `store.svelte.js` mirrors it and must be kept in sync.

**One binary, several modes** (`main.rs`): `ibrae hook` (fallback hook client), `hooks install|uninstall`, `uninstall-cleanup` (run by both NSIS `windows/hooks.nsh` and MSI `windows/msi-cleanup.wxs` uninstallers), otherwise the GUI.

**Claude Code integration** (`src-tauri/src/claude/`):
- `hooks.rs` edits `~/.claude/settings.json` (backup first, leaves other hooks alone) to register async hooks for PreToolUse/PostToolUse/UserPromptSubmit/Notification/Stop/SessionStart/SessionEnd/SubagentStart/SubagentStop pointing at `island-hook` next to the app exe. `repair()` runs at startup and reinstalls when any event in `EVENTS` is missing (`missing_events`), so new events reach existing users.
- `island-hook` (`src-tauri/hook/`) is a separate tiny crate (std + serde_json only) that `#[path]`-includes `src/claude/hookclient.rs` — that file is shared between the sidecar and the app's `hook` mode, so it must stay dependency-free beyond std/serde_json. Its `slim()` forwards `agent_id`, `agent_type` and `tool_input.subagent_type`. It is bundled as a Tauri `externalBin`, hence `build:hook` runs before dev/build.
- `ipc.rs` is the server: named pipe on Windows (duplex, rejects remote clients), Unix socket 0600 in `XDG_RUNTIME_DIR` on Linux; one JSON message per connection, ended by a newline (older clients just close). The handler gets the message plus a `Conn` it can answer on. **It is also the single-instance guard** — if `serve` can't claim the channel, the process exits before Tauri starts.
- `permission.rs` answers permission prompts. `PermissionRequest` is the one **synchronous** hook (no `async`, `timeout` 600; `repair()` treats an async one as stale). `hookclient` sends it and waits on the same connection for `{"decision":"allow"|"always"|"deny"}`, then prints Claude Code's `hookSpecificOutput` (`always` = allow + the request's own `permission_suggestions` as `updatedPermissions`). It skips `AskUserQuestion`/`ExitPlanMode`. The island keeps the `Conn` until the user clicks (`claude_permission`) and emits `claude-perm`. A request is dropped (connection closed = no decision, the terminal decides) when its hook dies, on `PostToolUse` of that tool, `Stop`/new prompt (main thread), `SubagentStop`, `SessionEnd`, after ~585 s (main) or 30 s (subagents: Claude Code may hold its own prompt for background agents until the hook returns), or immediately when `claude_approve` is off. In the main session the terminal dialog runs concurrently and the first answer wins.
- `mod.rs` turns events into per-session state (phase LEER/EDITAR/PROBAR/LISTO, diff preview, permission waits), drops stale out-of-order events by hook timestamp, and emits the most recently active session. The state logic is the pure `apply(map, ev, now) -> Applied`, which `handle()` wraps (lock, apply, emit). Each `Session` has `agents: Vec<Agent>`; events carrying `agent_id` update only that agent, never the session's label/detail/diff. A subagent's task comes from the main thread's `Agent`/`Task` PreToolUse (queued in `pending`, matched FIFO by `subagent_type` on `SubagentStart`).

**Window / hit-testing** (`hit.rs`): the window is a fixed transparent 760×330 rect at the top of the screen, click-through by default. The UI reports the island's hit rect via `set_hit_rect`; a background loop reads the cursor and drives away → ghost → active states (dwell time, Ctrl to force open), and emits `covered` when a maximized/fullscreen window is on that monitor. On Windows the same loop re-asserts `HWND_TOPMOST` (`keep_on_top`) when a normal window ends up above the island, which Windows sometimes does while keeping the topmost flag. `WIN_W` must match between `hit.rs` and `src/App.svelte`. Which monitor comes from `settings.monitor` ("primary", "cursor" or a key from `monitors.rs`: the monitor device path on Windows via the DisplayConfig API, so it survives replugging; the output name elsewhere); `place_window` picks it, and `monitor_tick` (run from the cursor loop on Windows, from `watch_covered` on Linux) re-places on display changes every ~2 s (on Windows also when the window was moved under it: Windows 11 puts windows back on a re-plugged monitor seconds later, and hover is tested against the cached origin) and, in "cursor" mode, follows the cursor once it rests 1 s on another monitor, never while the island is open. On Linux, native hover may be unavailable (`hover_native` returns false) and `App.svelte` falls back to DOM hover; Wayland sessions are forced onto XWayland (`GDK_BACKEND=x11`). XWayland can't see native Wayland windows, so on Plasma Wayland `kwin.rs` loads a KWin script over D-Bus (`org.kde.kwin.Scripting`) that calls back `dev.dynamicisland.Island.Covered(b)` and pins the island to the top edge over a top panel (KWin otherwise places X11 windows below panels; the script must skip GTK's hidden helper window from the same pid); other desktops use the X11/EWMH check in `hit.rs`. On Linux, `App.svelte` detects the cursor leaving by checking pointer events against the hit rect, and `hit.rs` forwards GTK crossings as `pointer-left` / `pointer-entered`; pointer events are ignored between the two because WebKitGTK follows each leave with a synthetic `pointermove` at the exit point (still inside the island).

**Platform split**: `#[cfg(windows)]` / `#[cfg(target_os = "linux")]` modules — e.g. `media/windows.rs` (SMTC) vs `media/linux.rs` (MPRIS via zbus), Win32 APIs in `hit.rs`/`ipc.rs`/`settings.rs` (registry autostart) vs X11 (`x11rb`) / `~/.config/autostart`. Changes to shared Rust code must compile on both; Windows is the primary tested platform, Linux is mostly compile-verified (see README "Estado").

**Memory budget**: WebView2 flags in `tauri.conf.json` (`--disable-gpu`, single renderer, V8 lite mode, etc.) are intentional RAM optimizations; the release profile is size-optimized with `panic = "abort"`. Don't remove them casually.

**Calendar** (`calendar.rs`): read-only iCal feeds (Google's "secret address in iCal format", Outlook, iCloud) stored in `settings.calendars` — no OAuth. A worker downloads them every 5 min (or at once when the list changes, via `refresh_now`), keeps the last good copy per feed, expands RRULE/EXDATE/RECURRENCE-ID with the `rrule` crate from yesterday to tomorrow and emits `calendar` only when the result changed. No network while no calendar is configured. Meeting links (Meet/Zoom/Teams/Webex) are pulled from the event fields; `open_url` opens https links only. The UI side (`calPill()` in the store) decides the pill: `cal-next` within `cal_notify_mins`, `cal-alert` (pill grows to a 460×84 card) from 1 min before to 2 min after start, `cal-now` while in progress. The pill takes no clicks, so hovering the alert opens the Calendar tab, where "Unirse" lives.

**Volume and brightness** (`audio/`; platforms other than Windows and Linux report `available: false`): on Windows one COM thread (`audio/win.rs`) owns Core Audio. `IAudioEndpointVolumeCallback` on the default output reports volume/mute; `IMMNotificationClient` reports default-output and device-list changes (rebind on the thread). Changing the default output uses the undocumented `IPolicyConfig` (same as EarTrumpet), only for ids we listed. Brightness: `PowerSettingRegisterNotification(GUID_VIDEO_CURRENT_MONITOR_BRIGHTNESS)` reports every change; WMI `WmiSetBrightness` sets it (needs `CoSetProxyBlanket`); no instance (desktops, external monitors) = `brightness: null`. Commands are coalesced to the last value so slider drags stay smooth. The core emits `audio` with a `cause` (volume/mute/output/brightness, none at startup); the store turns it into `osd` (respecting `osd_*` settings and `osd_ms`), `App.svelte` gives it the whole pill, and hovering it opens Sistema → Sonido y pantalla. Windows 11's own volume flyout can't be hidden (it's part of explorer now), so both show. Linux (`audio/linux.rs`) shells out to `pactl` with `LC_ALL=C` (PipeWire's pulse server or PulseAudio): `pactl subscribe` sink/server lines trigger a re-read, and the cause is derived by diffing with the previous state; without `pactl` it falls back to `wpctl` polled every 1 s (no output list). Brightness comes from `/sys/class/backlight` (firmware > platform > raw), polled every 300 ms because sysfs doesn't notify, and is set via logind `Session.SetBrightness` (no root), else by writing the file. The output parsers live in `audio/parse.rs` as pure functions with tests. KDE/GNOME show their own OSD too.

**Updates** (`update.rs`): checks `latest.json` of the newest GitHub release at startup (+30 s) and every 12 h when `check_updates` is on; a 404 (release built without the signing key) means "no info", not an error. Only installs by itself when installed with NSIS (`uninstall.exe` next to the exe) or MSI, or when running as an AppImage (`APPIMAGE` set), via `tauri-plugin-updater` (Windows and Linux dependency, `installMode: passive`, pubkey in `tauri.conf.json`); the AppImage file is replaced in place and the app restarts with `ISLAND_RESTART=1`, which makes `main.rs` retry claiming the Claude channel for ~6 s while the old process exits. Portable, .deb and .rpm just open the release page. As an AppImage (new mount path every run), `hooks.rs` points Claude Code at a copy of `island-hook` in `~/.local/share/dev.dynamicisland.island/`, refreshed by `repair()`. Dev aids: `ISLAND_UPDATE_URL` (another latest.json) and `ISLAND_UPDATE_NOW=1` (check and install at startup) test an update end to end. The `latest` job in release.yml writes `latest.json` from both build jobs' signatures (`.github/latest-json.mjs`). CI signs the update packages with the `TAURI_SIGNING_PRIVATE_KEY`/`_PASSWORD` repo secrets and `.github/latest-json.mjs` writes `latest.json`; without the secrets the build still works but that version can't be auto-updated to. Never lose the private key: installed copies only accept updates signed by it. `hooks.nsh` skips the uninstall cleanup when `$UpdateMode` is set.

**Naming**: the brand is written **IBRÆ** wherever we render text (UI, tray tooltip, window title, README, release titles). Anything the OS or package managers see is ASCII: `productName` `IBRAE` (install folder `%LOCALAPPDATA%\IBRAE`, Start menu, autostart entry), `mainBinaryName`/Cargo package `ibrae`, assets `IBRAE_<v>_x64-setup.exe` / `ibrae_<v>_amd64.deb`, npm package `ibrae-desktop`, repo `ibrarmz/ibrae`. A non-ASCII install path would end up in the Claude Code hook command, which runs through a shell. Internal names from the "Dynamic Island" days stay on purpose so existing installs keep working: the identifier `dev.dynamicisland.island` (data folder), the pipe/socket `dynamic-island`, the KWin bus `dev.dynamicisland.Island`, the hook backup suffix. `migrate.rs` moves Windows users off the old install on first run (silent uninstall of `%LOCALAPPDATA%\Dynamic Island`, then reconnects hooks and autostart); `main.rs` also closes a still-running old `dynamic-island.exe` when it holds the Claude channel.
